# Save Plan to Workspace

When the user asks you to "create a plan" (계획을 세워줘, 계획을 작성해줘) or when you enter Planning Mode, you must always save the final plan document into the project's `_plan/YYYY-MM/` directory.

## Instructions
1. When generating a plan, create a real markdown file inside `_plan/YYYY-MM/`, creating the month directory if needed. Do not save new plans directly in `_plan/`.
2. **Filename Convention**: You must use the format `_plan/YYYY-MM/YYYYMMDD_NNN_Title.md`.
   - `YYYY-MM`: The current local month (e.g., 2026-07), matching the filename date.
   - `YYYYMMDD`: The current local date (e.g., 20260728).
   - `NNN`: A 3-digit sequence number starting from `001`. Check the month directory for existing files on the same date and increment the highest number (also check legacy root files during migration).
   - `Title`: A brief PascalCase or descriptive title (e.g., `MainScreenLayout`).
   - Example: `_plan/2026-07/20260728_001_MainScreenLayout.md`
3. If a plan for the exact same feature on the same day already exists, update it rather than creating a new file, unless otherwise requested. When updating a past plan, keep its original month and filename.
4. If you also use the standard `implementation_plan.md` artifact to get user approval, make sure the contents are synchronized or primarily written to the `_plan` directory.
5. This ensures that all development plans are properly persisted in the source control repository for future reference.
